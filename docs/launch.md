# 꾸그 연동과 실제 런칭 절차

이 문서는 "AI 영어 선생님"을 꾸그 웹사이트에 붙여 실제로 판매하기까지의 순서입니다. 코드 연동 지점은 `docs/integration.md`, 원가는 `docs/cost-model.md`를 참고하세요.

## 0. 한눈에 보기

```
꾸그 웹/앱 ──(로그인 토큰)──▶ ai.gguge.com (이 앱)
   │                              │
   │  상품 구매 / 이용권 차감       │  세션 생성 시 결제 확인 → 수업 → 리포트
   ▼                              ▼
꾸그 결제·회원 API  ◀──(webhook)── 수업 결과(리포트, 사용량, 원가) 저장
```

권장 형태: 이 앱을 **별도 서브도메인**(예: `ai.gguge.com`)에 배포하고, 꾸그에서는 "AI 영어 선생님" 상품 페이지의 [수업 시작] 버튼이 로그인 토큰을 붙여 이 앱으로 넘깁니다. 꾸그 본체 코드를 거의 건드리지 않고, 앱을 독립적으로 배포·롤백할 수 있습니다.

## 1. 상품 설계 (기획)

| 항목 | 제안 |
|---|---|
| 상품명 | AI 영어 선생님 코코 (1:1 스피킹) |
| 가격 | 시간당 1,000원. 실제 판매 단위는 10/20/30/60분 수업권 (167/333/500/1,000원) 또는 "AI 수업 시간 충전"(예: 5시간 5,000원) |
| 대상 | 초등 1~6학년, 레벨 3단계 |
| 진입 | 꾸그 마이페이지 또는 상품 페이지 → [지금 수업 시작] |
| 결과물 | 수업 직후 학부모 리포트(앱 화면 + 꾸그 알림/카카오톡) |
| 환불 규칙 | 첫 턴 실패 시 자동 미차감. 수업 중 이탈은 소진 처리. 서비스 장애(우리 쪽 오류)로 3턴 이상 실패 시 자동 환급 |

첫 판매 단위는 **20분 수업권(333원)** 을 권합니다. 아이 집중 시간과 맞고, 원가 대비 마진 계산이 단순합니다.

## 2. 기술 연동 (개발)

### 2-1. 배포

- Vercel 또는 AWS(ECS/Fargate)에 Next.js 앱 배포. 도메인 `ai.gguge.com`.
- 환경변수: `ANTHROPIC_API_KEY`, `TUTOR_MODEL`, `KRW_PER_USD`, 그리고 아래 연동용 `GGUGE_JWT_PUBLIC_KEY`, `GGUGE_API_BASE`, `GGUGE_WEBHOOK_SECRET`.
- 세션 저장소를 Redis 로 교체 (`SessionStore` 구현체 하나 추가). Vercel 이면 Upstash Redis 가 간단합니다.

### 2-2. 인증 (꾸그 로그인 그대로 쓰기)

1. 꾸그에서 [수업 시작] 클릭 시 짧은 수명(5분)의 서명 토큰(JWT)을 만들어 `https://ai.gguge.com/start?token=...` 로 이동. 토큰에는 `userId`, `childId`, `childName`, `age`, 최근 레벨 판정이 들어갑니다.
2. 이 앱의 `/start` 라우트가 토큰을 검증하고, 자체 세션 쿠키를 발급한 뒤 설정 화면(또는 바로 수업)으로 보냅니다.
3. `/api/sessions/*` 는 쿠키의 `userId` 와 세션의 소유자를 대조합니다.

꾸그가 이미 OAuth/SSO 를 쓰고 있다면 그 방식을 그대로 따르면 됩니다. 핵심은 "아이 프로필을 꾸그가 넘겨주고, 이 앱은 그 안에서만 동작"하는 것입니다.

### 2-3. 결제/수업권 차감

- `POST /api/sessions` 가 세션을 만들기 전에 꾸그 결제 API 를 호출해 `priceKrw(durationMin)` 만큼 **홀드**합니다. 실패하면 402 로 응답하고 화면은 충전 페이지로 안내합니다.
- 첫 턴이 성공해 세션이 `active` 가 되는 순간 홀드를 **확정** 차감합니다. 첫 턴이 실패하면 홀드를 해제합니다.
- 세션 종료(리포트 생성) 시 꾸그로 webhook: 세션 ID, 아이 ID, 사용 시간, 리포트 JSON, 토큰 사용량, 추정 원가.

### 2-4. 꾸그 화면에 넣을 것

- 상품 페이지와 [수업 시작] 버튼 (레벨/주제/길이 선택은 이 앱에서 처리).
- 마이페이지 "AI 수업 기록": webhook 으로 받은 리포트 목록. `level_signal` 누적으로 다음 수업 레벨 추천.
- 알림: 수업 끝나면 학부모에게 리포트 링크(카카오 알림톡/앱 푸시).

### 2-5. 앱(WebView) 대응

- 안드로이드 WebView 는 브라우저 음성 인식이 막힌 경우가 많습니다. 앱에서는 네이티브 STT 결과를 텍스트로 주입하는 브리지를 두거나, 1차 런칭은 **모바일 웹 브라우저(Chrome)와 PC** 로 한정합니다.
- iOS Safari 는 음성 인식이 제한적입니다. 런칭 안내에 "Chrome/Edge 권장"을 명시합니다.

## 3. 운영 준비

- **원가 모니터링**: 세션마다 `usage`/`aiCostKrw` 를 저장하고, 일 단위로 판매가 대비 원가 비율을 봅니다. 60% 를 넘는 세션이 많으면 `TUTOR_MODEL` 을 Sonnet 5 / Haiku 4.5 로 조정합니다.
- **남용 방지**: 세션당 최대 턴 수(예: 80), 발화 길이 600자 제한(이미 적용), 계정당 동시 세션 1개, IP 단위 세션 생성 속도 제한.
- **키 관리**: Anthropic Console 에서 워크스페이스를 분리하고 월 지출 한도를 설정합니다. 키는 서버 환경변수에만 둡니다.
- **장애 대응**: Anthropic API 장애 시 화면에 "잠시 후 다시" 안내 + 세션 시간 정지(서버 시계 보정) + 자동 환급 규칙.
- **아동 안전**: 프롬프트의 안전 규칙 외에, 리포트에 걱정되는 발화 플래그를 추가해 운영자가 확인하는 흐름을 둡니다.
- **개인정보**: 14세 미만 보호자 동의(꾸그 가입 시 이미 받았다면 AI 수업 항목 추가), 대화 기록 보관 기간 명시(예: 90일), Anthropic 데이터 정책 안내. 이름·나이 외 개인정보는 프롬프트에 넣지 않습니다.

## 4. 런칭 단계

| 단계 | 기간 | 내용 | 통과 기준 |
|---|---|---|---|
| 내부 테스트 | 1주 | 팀원 자녀·지인 10명, 데모 페이지와 로컬 앱 | 20분 수업 완주율 80%, 치명 오류 0 |
| 클로즈드 베타 | 2~3주 | 꾸그 기존 고객 30~50가정, 무료 수업권 3회 | 재수업률 40%, 학부모 리포트 만족도 4/5, 세션당 원가 판매가의 60% 이하 |
| 모델·가격 확정 | 베타 중 | Opus 5 vs Sonnet 5 vs Haiku 4.5 를 세션 단위로 섞어 리포트 품질과 원가 비교 | 기본 모델 1개 확정 |
| 정식 오픈 | - | 상품 페이지 공개, 20분 수업권 판매, 알림톡 리포트 | 첫 달 원가율과 이탈률 주간 리뷰 |

## 5. 런칭 전 체크리스트

- [ ] `ai.gguge.com` 배포, HTTPS, 환경변수 설정
- [ ] Redis 세션 저장소 교체, 분산 락
- [ ] 꾸그 SSO 토큰 검증 라우트(`/start`)와 세션 소유권 검사

- [ ] 리포트 webhook, 꾸그 마이페이지 수업 기록
- [ ] 세션당 원가 로그와 일간 대시보드
- [ ] 남용 제한(턴 수, 동시 세션, 속도 제한)
- [ ] 브라우저 안내(Chrome/Edge), 마이크 권한 안내 화면
- [ ] 보호자 동의 항목, 데이터 보관 정책 문구

- [ ] 베타 가정 모집과 피드백 폼
