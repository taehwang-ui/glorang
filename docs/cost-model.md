# 시간당 원가 모델

목표: 판매가 **1,000원/시간**에서 AI 원가가 얼마나 드는지, 어떤 모델을 골라야 하는지.

계산 함수는 `src/lib/billing/cost.ts`의 `estimateHourUsage`/`estimateHourKrw`이고, `tests/cost.test.ts`가 기본 시나리오가 예산 안에 있는지 확인합니다.

## 가정 (1시간 수업)

| 항목 | 값 | 근거 |
|---|---|---|
| 학생 턴 수 | 40회 | 아이 발화 주기 약 90초 (STT 대기 + 선생님 TTS 시간 포함) |
| 시스템 프롬프트 | 1,200 토큰 | 고정 지침 + 세션 프로필, 전부 캐시 |
| 턴당 이력 증가 | 120 토큰 | 학생 40 + 선생님 80 |
| 선생님 출력 | 80 토큰 | 1~3문장, 레벨별 20~50단어 상한 |
| 사고(thinking) 토큰 | 100 토큰/턴 | Opus 5 effort=low 가정. Haiku는 사고 없음 |
| 리포트 | 입력 6,000 / 출력 700 토큰 | 수업 1회당 1번 |
| 환율 | 1,400원/달러 | `KRW_PER_USD` 로 조정 |

단가(백만 토큰당, USD): Opus 5 입력 5 / 출력 25 / 캐시읽기 0.5 / 캐시쓰기 6.25. Sonnet 5 는 2 / 10 / 0.2 / 2.5. Haiku 4.5 는 1 / 5 / 0.1 / 1.25.

## 결과

| 시나리오 | Opus 5 | Sonnet 5 | Haiku 4.5 |
|---|---|---|---|
| 기본 (40턴, 사고 100) | **479원** | 192원 | 96원 |
| 사고 0 | 339원 | - | - |
| 말 많은 아이 (60턴, 사고 250) | **1,047원** | 419원 | 104원 |

기본 시나리오의 토큰 구성: 입력 7,600 / 출력 7,900 / 캐시읽기 140,400 / 캐시쓰기 5,880. 입력의 90% 이상이 캐시 읽기라서 캐시가 깨지면 원가가 몇 배로 뜁니다. `usage.cache_read_input_tokens` 가 0이면 즉시 조사해야 합니다.

턴당 평균 원가(Opus 5): 약 10원. 리포트 1회: 약 66원.

## 판단

- **Opus 5 (현재 기본)**: 가장 자연스러운 선생님. 기본 시나리오는 판매가의 48%지만 말이 많은 세션은 적자. 파일럿에서 품질 기준을 잡는 용도.
- **Sonnet 5**: 원가 19~42%. 품질과 마진의 절충.
- **Haiku 4.5**: 원가 10%. 1,000원 가격에서 안전한 마진. 아이 대상 짧은 대화에는 충분할 가능성이 높으나 교정 품질을 파일럿으로 확인해야 함.

권장: 파일럿 첫 주는 Opus 5로 "좋은 수업"의 기준을 만들고, 같은 프롬프트로 Haiku/Sonnet 세션을 섞어 리포트 품질과 학부모 만족도를 비교한 뒤 기본 모델을 확정. 세션마다 `aiCostKrw` 가 기록되므로 실제 분포로 다시 계산하면 됩니다.

## 원가에 영향을 주는 설계

1. **고정 지침을 바이트 단위로 동일하게 유지** (`TUTOR_CORE_PROMPT`). 날짜·이름·ID를 넣지 않는다. 모든 세션이 같은 캐시를 공유한다.
2. **세션 프로필은 두 번째 system 블록**에, **이력은 마지막 user 메시지에 브레이크포인트**. 턴 간격이 5분 이내라 5분 TTL로 충분.
3. **effort=low, max_tokens=1500**: 사고 토큰과 출력 길이를 묶어서 제한.
4. **음성은 브라우저에서**: 클라우드 STT/TTS를 쓰면 시간당 수천 원이 추가되어 1,000원 구조가 깨진다. 품질 문제로 교체할 경우 아이가 실제로 말하는 시간(시간당 10~15분)만 과금되도록 VAD로 잘라 보내야 한다.

## 인프라 원가 (참고)

스트리밍 API 라우트 하나와 인메모리 세션이라 서버 부하는 작습니다. 세션당 동시 연결 1개, 대부분의 시간은 TTS/STT로 브라우저에서 소비됩니다. 서버리스(Vercel 등)에서는 스트리밍 응답 시간(턴당 수 초)만 과금됩니다.
